# Create: SoftMotion

**[English](README.md)** | **Русский**

[![Modrinth](https://img.shields.io/badge/Modrinth-createsoftmotion-blue)](https://modrinth.com/mod/createsoftmotion)
![MC](https://img.shields.io/badge/Minecraft-1.19.2-green) ![loader](https://img.shields.io/badge/Forge%2043.2%2B%20%7C%20Fabric%200.15%2B-orange)

Клиентский аддон доступности для [Create](https://modrinth.com/mod/create): замедляет **визуальное**
вращение механизмов и конструкций Create для игроков со зрительной гиперчувствительностью.

- Замедляется только отрисовка вращения: рендер-инстансы Flywheel (`KineticData.setRotationalSpeed`),
  Mechanical Bearing (`getInterpolatedAngle`) и сущности конструкций на вращателе (`setAngle`).
- **Не меняет** кинетику Create: RPM, нагрузку (stress), кинетические сети, поведение конструкций,
  скорость обработки предметов и вообще игровую логику — меняется только картинка.
- Только клиент: работает в одиночной игре и на серверах, на выделенном сервере не нужен.

## Настройки — `config/softmotion-client.toml`

| Опция | По умолчанию | Значение |
|---|---|---|
| `visualSpeedMultiplier` | `0.25` | `0.0` — визуальное вращение заморожено, `0.25` — в четыре раза медленнее, `1.0` — обычные визуальные скорости Create. Используется, если формула пуста, и как запасной вариант при ошибке в формуле |
| `visualSpeedFormula` | `""` | необязательная формула, вычисляемая для каждого элемента; если не пуста, перекрывает `visualSpeedMultiplier` |
| `slowBearingContraptions` | `true` | замедлять также сущности конструкций, собранных на механическом вращателе |

Экран настроек открывается из списка модов (через `IConfigScreenFactory` NeoForge). Если NeoForge не
предоставляет `ConfigurationScreen`, мод продолжает работать с TOML-файлом. В Forge/Fabric-сборках этой
ветки универсального экрана настроек нет — настройки меняются в TOML-файле (на Fabric он создаётся
с значениями по умолчанию при первом запуске).

### Синтаксис формулы

Формула возвращает **множитель реальной скорости**, ограниченный диапазоном `0.0..1.0`. Она
вычисляется отдельно для каждого вращающегося элемента, поэтому замедление может зависеть от того,
насколько быстро он на самом деле крутится.

Переменные:

| Имя | Значение |
|---|---|
| `rpm` | реальная абсолютная скорость элемента в единицах Create (значение скорости Create, «RPM») |
| `speed` | `rpm * 6` — единица скорости Flywheel (градусы в секунду) |

Операторы: `+ - * / % ^` (`^` — степень, правоассоциативна), сравнения (`< <= > >= == !=`),
логические `&& || !` и тернарный оператор `условие ? a : b`. Константы: `pi`, `e`.
Функции: `abs`, `min`, `max`, `clamp`, `sqrt`, `sign`, `floor`, `ceil`, `round`, `pow`, `log`,
`exp`, `sin`, `cos`, `tan`, `if(условие, a, b)`.

Примеры:

```toml
visualSpeedFormula = "min(1, 8 / (rpm + 0.001))"        # быстрые механизмы замедляются сильнее
visualSpeedFormula = "clamp(0.25 + rpm / 200, 0.1, 1)"  # плавная зависимость от скорости
visualSpeedFormula = "if(rpm > 100, 0.1, 0.5)"          # два диапазона скоростей
```

Ошибочная формула один раз пишется в лог, после чего используется обычный `visualSpeedMultiplier`.
Формула компилируется один раз при изменении конфига, а не на каждом кадре.

## Сборка

Ветка нацелена на Minecraft 1.19.2 и собирается мульти-модульным туслчейном
[Architectury](https://modrinth.com/mod/architectury-api) (`architectury-plugin` + `dev.architectury.loom`):
`common` (миксины, математика, фасад конфига), `forge` (Forge 43.2.4+) и `fabric` (Fabric Loader 0.15+).

Для запуска Gradle нужен JDK 17–21 (wrapper — Gradle 8.12, он не принимает более новые JVM) и доступ в
интернет при первой сборке (loom, ассеты Forge userdev, джарники Create 0.5.1.i с maven Modrinth —
на `maven.createmod.net` для MC 1.18/1.19 ничего нет). Джарники flywheel и Registrate лежат в репозитории
в `libs-maven/`, потому что они поставляются только вложенными внутрь джарника Create; каталог
перегенерирует скрипт `fetch-libs.sh`.

```bash
./gradlew build
# forge:  forge/build/libs/create-softmotion-forge-1.1.1+1.19.2.jar
# fabric: fabric/build/libs/create-softmotion-fabric-1.1.1+1.19.2.jar
./gradlew :forge:runClient   # dev-клиент с Create 0.5.1.i
./gradlew :fabric:runClient  # dev-клиент с create-fabric 0.5.1-i-build.1630
```

Ветка main — NeoForge-сборка для 1.21.1; остальные версии Minecraft живут в отдельных ветках
(`mc1.20.1`, `mc1.19.2`, `mc1.18.2`, `mc1.16.5`).

| Сторона | только клиент (`client_side: required`, `server_side: unsupported`) |

Замечание: порт create-fabric для этой версии Minecraft находится в статусе BETA (сборка 1630);
Fabric-сборка SoftMotion нацелена именно на эту бета-линию. Forge-сборка нацелена на стабильный
Create 0.5.1.i.

Все инъекции идут с `require = 0`, а в конфиге миксинов стоит `defaultRequire = 0`: если будущая сборка
Create переименует цель, мод не упадёт при запуске — просто эта инъекция не применится. Совместимость с
другими версиями Minecraft и Create не гарантируется.

## Как это работает

`visualSpeedMultiplier` (или результат формулы) применяется только к визуальному углу / скорости вращения:

- `KineticData.setRotationalSpeed` — единая точка, через которую каждый рендер-инстанс Flywheel в
  Create 0.5.1 (валы, шестерни, конвейеры, миксеры) получает скорость отрисовки; масштабируется именно
  она, а block entity сохраняет реальные обороты;
- `MechanicalBearingBlockEntity.getInterpolatedAngle` — возвращаемый угол заменяется локально
  просчитанным *визуальным* углом, который следует за реальным в заданном отношении (интегрирование по
  кратчайшей разнице, поэтому переход через 360° не даёт скачка);
- `ControlledContraptionEntity.setAngle` — то же состояние визуального угла для сущностей конструкций;
  пропускается, если `slowBearingContraptions` выключен или множитель равен `1.0`.

Состояния визуальных углов хранятся в `WeakHashMap`, поэтому block entity и сущности не утекают в памяти.

### Известные ограничения

- Визуальный угол следует за реальным через кратчайшую разницу. Если между двумя отрисовками реальный
  угол меняется более чем на 180° (очень высокие обороты при низком FPS), интеграция может принять это
  за вращение в противоположную сторону.
- Для вращателей и сущностей собранных конструкций миксины не получают скорость напрямую, поэтому
  переменная `rpm` оценивается по изменению реального угла за время (со сглаживанием); результаты
  формулы для этих элементов приблизительны. Для валов и других Flywheel-инстансов скорость точная.
- Результат ограничен диапазоном `0.0..1.0`: формула может только замедлять картинку, но не ускорить её
  сверх обычной скорости Create.
